## 1. What it is and where it lives

OpenClaw — a multi-channel agent gateway: one WebSocket gateway process serving a "Control UI"
SPA, plus a CLI, chat-channel bridges, sandboxes, node hosts and plugins. MSO uses it for
exactly three things: one status card, its Control UI routes as MSO app tiles, a read-only CLI
view.

| | Value | Verified by |
|---|---|---|
| Version | `OpenClaw 2026.7.1-2 (0790d9f)` | `openclaw --version` |
| Install method | global npm under `~/.local` | path below |
| CLI | `/home/rahman/.local/bin/openclaw` | `which openclaw` |
| Install dir | `~/.local/lib/node_modules/openclaw` (370 MB) | unit `ExecStart`, `du -sh` |
| State dir | `~/.openclaw` (1.7 GB — **separate from the install**, unlike Hermes) | `catalog.ts:37`, `du -sh` |
| Gateway port | `18789`, bound `0.0.0.0` (because `gateway.bind: "lan"`) | `ss -tlnp`, `~/.openclaw/openclaw.json` |
| Public today | **yes** — `oc.rahmanef.com` (`200`) | `/etc/dokploy/traefik/dynamic/oc-openclaw.yml` → `http://172.17.0.1:18789`, `passHostHeader: true` |
| MSO app host | `openclaw.mso.rahmanef.com` → mso `:4005` → proxy → `127.0.0.1:18789` | `mso-managed-apps.yml`, `curl` in §5 |

One **user** systemd unit, `~/.config/systemd/user/openclaw-gateway.service`. There is no
system-scope unit, and no `openclaw.service` — that name does not exist on this host, which is why
§2 starts with which unit MSO actually drives.

```
Environment=OPENCLAW_SERVICE_KIND=gateway  OPENCLAW_SERVICE_VERSION=2026.6.10
```

`OPENCLAW_SERVICE_VERSION=2026.6.10` and `Description=OpenClaw Gateway (v2026.6.10)` are **stale** —
the installed CLI is `2026.7.1-2`. The unit is generated by `openclaw daemon install` and stamps the
version that wrote it, so it drifts on any upgrade that does not re-install the service. Cosmetic, but
it is the signal that the *unit is written by the app*, not by hand — see §7.

own `.pre-update` / `.last-good` / `.bak*` snapshots, `credentials/`, `identity/`, `devices/`,
`logs/`, `plugin-skills/`, `skill-workshop/`, `exec-approvals.json`, and `workspace/` — agent
workspaces, each with its own `node_modules`.

**`gateway.bind: "lan"` is why the port is on `0.0.0.0`,** which lets Traefik reach it across
the docker bridge for `oc.rahmanef.com`. MSO does not depend on it: the proxy targets
`127.0.0.1:18789` and would keep working if the bind were narrowed to loopback.

## 2. How MSO detects and controls it

Catalog entry at `lib/managed-apps/catalog.ts:27`.

| Field | Value |
|---|---|
| `command` | `openclaw` |
| `serviceNames` | `["openclaw-gateway.service", "openclaw.service"]` — live unit first |
| `containerNames` | `["openclaw", "openclaw-gateway"]` |
| `dashboardUrl` | `http://127.0.0.1:18789` (`OPENCLAW_DASHBOARD_URL`) |
| `stateDirName` | `.openclaw` |
| overrides | `OPENCLAW_CONTROL_UI_DIST` (discovery only) |

### Which unit MSO actually drives

**`openclaw.service` does not exist on this host.** The running unit is
`openclaw-gateway.service`, and detection checks each candidate's `LoadState` before accepting it
(`manager.ts:29`), so that is the one it lands on:
`systemctl --user show -p LoadState -p ActiveState openclaw.service openclaw-gateway.service` →
`not-found`, then `loaded` + `active`. `listManagedApps()` returns `installationType: "systemd"`,
**`state: "running"`**, `healthy: true`, `dashboardAvailable: true`, version
`OpenClaw 2026.7.1-2 (0790d9f)`, `supportedActions: ["start","stop","restart","backup"]`.

The trap worth carrying forward: `systemctl is-active <unknown-unit>` prints `inactive` with rc 4 and
an empty stderr on systemd 255, byte-identical to a stopped unit. Read that as "the unit exists" — as
the first version of this code did — and the phantom `openclaw.service` wins detection: the card read
"stopped" while the gateway served, `journalctl -u openclaw.service` returned the one line
`-- No entries --`, and every lifecycle action `409`d on a unit that was not there. The catalog now
lists the live unit first (`catalog.ts:34`), but that ordering is a preference; `LoadState` decides
([MANAGED-APPS.md §3](./MANAGED-APPS.md)).

- **Logs** are that unit's journal: `available: true`, 100 lines, redacted (`manager.ts:18`).
- **`start`/`stop`/`restart`** run `systemctl --user <action> openclaw-gateway.service`
  (`manager.ts:121`), system scope only if that fails. They restart the **gateway**, dropping
  connected channel bridges and Control-UI sockets — the same blast radius as OpenClaw's own
  `openclaw daemon start | stop | restart | status`.
- **The dashboard never depended on detection.** The proxy and discovery go straight at
  `dashboardUrl`, which is why a wrong card was the *only* symptom, and why it went unnoticed.

### The rest of the lifecycle

**Health** is genuinely meaningful here — unlike Hermes:
`curl -s http://127.0.0.1:18789/health` → `200`, `application/json`, **unauthenticated**, no
redirect, body `{"ok":true,"status":"live"}`. `response.ok` is a real liveness answer.

**Version** is `openclaw --version`, a single line, so nothing is truncated.

**`backup` copies `~/.openclaw`** (no `OPENCLAW_HOME` exists, so that path is always the source).
With the exclusions in [MANAGED-APPS.md §6](./MANAGED-APPS.md) it is **237 MB** instead of 1.7 GB —
`~/.openclaw/workspace` alone drops 1.2 GB → 83 MB once one agent workspace's `node_modules` and
`.venv` are pruned (`du -sh --exclude=node_modules --exclude=.venv ~/.openclaw/workspace`). Symlinks
are skipped, not refused: `find ~/.openclaw -type l | wc -l` → **2063**, all but 9 inside those
pruned trees, and those 9 are `plugin-skills/{browser-automation,canvas}`, the Chromium
`browser/openclaw/user-data/Singleton{Socket,Cookie,Lock}` links and four
`agents/main/agent/codex-home/tmp/arg0/*` wrappers — none of which a restore should recreate; the
first of them is what used to abort the run. OpenClaw's own `openclaw backup` ("Create and verify
local backup archives for OpenClaw state") is still the only path that *verifies* an archive, and
the updater snapshots `openclaw.json` itself.

## 3. Auth model, and how the proxy lives with it

**OpenClaw sets no cookies at all.** Verified two ways: the live gateway returns no
`Set-Cookie` on `/`, `/health`, `/config`, `/status`, `/rpc` or `/v1/status`, and the Control
UI bundle reads none — the only `cookie` matches in `dist/control-ui/assets/*.js` are two in
`tool-display-*.js`, inside an `authorization|cookie|x-api-key|…` **redaction** pattern for
displaying tool output. That is the fact `proxy-headers.ts:41-45` records, and it is why the
`mapp_openclaw_` namespace carries nothing today — it exists so a future upstream cookie
cannot collide with the cockpit's `session`, or with Hermes' five.

Its auth is a **gateway token presented over the WebSocket**. From `openclaw.json`:
`gateway.auth.mode = "token"` (the token itself is in that file; MSO never reads it),
`gateway.bind = "lan"`, `gateway.controlUi.allowInsecureAuth = true`,
`gateway.controlUi.allowedOrigins = ["https://oc.rahmanef.com"]`.

**The handshake, captured live.** The gateway accepts an `Upgrade` on `/` — the same path that
serves the SPA — and immediately pushes a challenge before any credential is sent:

```
$ curl -i --http1.1 --max-time 2 -H 'Connection: Upgrade' -H 'Upgrade: websocket' \
       -H 'Sec-WebSocket-Version: 13' -H 'Sec-WebSocket-Key: <16 random bytes, base64>' \
       http://127.0.0.1:18789/
HTTP/1.1 101 Switching Protocols
{"type":"event","event":"connect.challenge","payload":{"nonce":"…","ts":…}}
```

(`--max-time` is not optional — after `101` curl holds the socket open and never exits.)

The upgrade is **not** origin-gated: it returns the same `101` and challenge with `Origin:
https://evil.example`, and gates at the protocol layer instead. `allowedOrigins` and
`allowInsecureAuth` govern the Control UI's own checks — and that allowlist names
`oc.rahmanef.com` only, **not** `openclaw.mso.rahmanef.com`. Costs nothing today (no socket
crosses the proxy); first thing to add if a socket proxy lands.

**Where the token lives client-side.** The SPA reads it from the URL **fragment**
`#token=<…>`, strips it, and persists it in `localStorage` under
`openclaw.control.token.v1` (plus a per-gateway `openclaw.control.token.v1:<gateway>`
variant, alongside `openclaw.control.currentGateway.v1:`, `openclaw.control.settings.v1`,
`openclaw.control.user.v1`). A `?token=` query still parses but logs *"Auth token passed as
query parameter (?token=). Use URL fragment instead: #token=<token>. Query parameters may
appear in server logs."* The supported way to get a URL is `openclaw dashboard --no-open`.

**MSO never mints, reads or injects that token.** `featureSource()` (`feature-cli.ts:102`)
builds the iframe `src` as `https://openclaw.mso.rahmanef.com/<route>` — origin plus path, no
fragment — and nothing in `lib/managed-apps/` reads `openclaw.json` (grep: the only upstream
reads are the control-UI assets and the gateway's HTTP surface). So the framed SPA starts with
**no gateway token** — the second independent reason its panels are empty (§4 is the first).
Injecting one would mean lifting a credential out of another application's config and putting
it in a URL, which is the boundary this subsystem exists to keep.

**So there is no login flow inside the frame at all**: no `302`, no form, no `Set-Cookie`,
nothing for `rewriteSetCookie()` to namespace, nothing for the re-entry guard to rescue.

## 4. The dashboard's shape, and what works through the proxy

A Vite/rolldown-built SPA at `~/.local/lib/node_modules/openclaw/dist/control-ui`, served by
the gateway itself. Three properties matter to the proxy:

- **`./`-relative asset URLs and no `<base>`** — `index.html` points at `./assets/…`,
  `./favicon.svg`, `./manifest.webmanifest`. Hermes is the opposite (§4 there).
- **The gateway is an SPA-fallback server**: every path returns the same 14 406-byte
  `index.html` (verified on `/config`, `/status`, `/rpc`, `/v1/status`) and serves `/assets` at
  any depth. That is why root-mounting works for nested routes like `/settings/appearance` even
  with relative URLs, and why origin-split mode needs **no** document rewriting — no
  `<base href>`, no rebasing, no fetch shim, nothing to hash-pin.
- **Two inline `<script>` blocks** (a theme bootstrap), matching exactly the two `sha256-`
  sources in its own `script-src` (§5).

It also ships `sw.js` + `manifest.webmanifest` and calls `navigator.serviceWorker.register(…,
{updateViaCache:'none'})`. OpenClaw is the reason the proxy refuses service-worker paths
outright (`route.ts:109`, `proxy-headers.ts:182`): a worker registered from proxied bytes
installs on *this* origin and keeps answering after the window closes. The emitted `worker-src`
is `'none'` too (§5), so it is closed twice.

### Why the panels are empty

**Every panel in the Control UI is driven by the gateway WebSocket.** The client builds its URL
from `location` — `${https ? 'wss' : 'ws'}://${location.host}<basePath>` — so on
`openclaw.mso.rahmanef.com` it targets that host, which is mso. **A Next route handler cannot
service an `Upgrade`**: it is handed a `Request` and returns a `Response`, and the proxy's
transport is `fetch()`. So the frame loads its chrome, HTML, CSS and JS — and sits with no data.

That is recorded as `SOCKET_FEATURES.openclaw = "all"` (`feature-cli.ts:42`), and it changes
the default view: `defaultView()` (`:60`) opens **on the CLI** for every OpenClaw feature that
has a command, because opening on the UI would be opening on a surface that cannot populate.
The UI toggle is still there, and the window states the reason rather than letting the
emptiness look like a bug. The one exception is **Appearance** (`/settings/appearance`), which
has no CLI equivalent, so it falls back to `"ui"` and opens on the empty panel with the notice.

Also inert in the frame: new-window links. `allow-popups` is deliberately absent from the
sandbox (`feature-app.tsx:107`); the four `window.open(` call sites across the control-UI
bundle are external links, ctrl-click terminal links and an open-in-editor deep link —
destinations for the user's own browser, not this frame.

### The CLI equivalents

Feature keys map to **verified read-only** `openclaw` subcommands (`feature-cli.ts:27`), each
checked against `openclaw --help` and its own `<command> --help` on this host. Several UI keys
share one command, so the map is many-to-one:

| Command | Keys |
|---|---|
| `chat` · `sessions` · `mcp` · `logs` · `worktrees` | the same-named key |
| `agents` | `agents`, `ai-agents` |
| `cron` | `cron`, `automation` |
| `tasks` | `tasks`, `dreams`, `workboard` (gated) |
| `skills` | `skills`, `skill-workshop` |
| `nodes` | `nodes`, `infrastructure`, `instances` |
| `channels` | `channels`, `communications` |
| `plugins` | `plugin` (gated) |
| `status` / `status --usage` / `audit` | `overview` / `usage` / `activity` |
| `config validate` / `doctor --lint` | `config` / `debug` |
| *none* | `appearance` — opens on the UI |

A bare group command is safe because the CLI view types into a live PTY and a group prints its
action list. Two commands are **not** safe bare and are deliberately mapped to their documented
read-only forms: `openclaw config` is *"Run without subcommand for guided setup"*, and
`openclaw doctor` prompts and applies repairs unless `--lint` / `--non-interactive`.
`feature-cli.test.ts` pins the map against the verbatim `--help` verb lists, so an upstream
rename fails a test rather than shelling something that writes.

## 5. Its own CSP and framing headers, and what the intersection does

OpenClaw ships a real policy and real framing refusal. Live, on every HTML response — read it
with a GET, because the two `sha256-` sources are derived from the body it is about to send
and a `curl -sI` (HEAD) returns the same policy with `script-src 'self'` and no hashes:

```
X-Frame-Options: DENY
Referrer-Policy: no-referrer
X-Content-Type-Options: nosniff
Permissions-Policy: camera=(), microphone=(self), geolocation=()
Content-Security-Policy: default-src 'self'; base-uri 'none'; object-src 'none';
  frame-ancestors 'none'; script-src 'self' 'sha256-xlWU9W5DLkdwhgKfV5ywIgqPfePNDkqtaKOBVD1gkB4='
  'sha256-YE++OxiPw+vXrIb7PDq83l6z34Hi3wFFCJVdIBVD5zU='; style-src 'self' 'unsafe-inline'
  https://fonts.googleapis.com; img-src 'self' data: blob:; media-src 'self' data: blob:;
  font-src 'self' https://fonts.gstatic.com; worker-src 'self';
  connect-src 'self' ws: wss: https://api.openai.com https://tweakcn.com
```

The response allowlist (`proxy-headers.ts:30`) copies **none** of those to the browser — an
upstream `X-Frame-Options: DENY` plus `frame-ancestors 'none'` would un-frame the dashboard,
the one thing the proxy exists to prevent. The policy is not discarded either: it is fed into
`contentSecurityPolicy()` and **intersected per directive** (`proxy-csp.ts:214`). Computed
from the live header, root-mounted:

```
default-src O; script-src O 'sha256-xlWU9W5…' 'sha256-YE++OxiP…';
style-src O 'unsafe-inline' https://fonts.googleapis.com; img-src O data: blob:;
font-src O https://fonts.gstatic.com; media-src O data: blob:; worker-src 'none';
connect-src O https://api.openai.com https://tweakcn.com; frame-src O; form-action O;
base-uri 'none'; frame-ancestors 'self' https://mso.rahmanef.com; object-src 'none'
        …where O = https://openclaw.mso.rahmanef.com/
```

Six things the intersection did, and why each is the right answer:

| Directive | Outcome | Why |
|---|---|---|
| `script-src` | lost `'unsafe-inline'`, gained OpenClaw's two `sha256-` | upstream grants no `'unsafe-inline'`, so the tighter side wins and its own inline scripts survive on the hashes it authored. Hashes copy, **nonces never** (`proxy-csp.ts:134`) — a nonce matches an element whatever its URL, re-opening origin scoping. Root-mounted MSO injects and pins nothing (`:233`); single-origin adds a third hash for its shim |
| `worker-src` | `'none'` | ours `blob:`-only ∩ theirs `'self'` = ∅ — this is what stops §4's service worker outliving the window |
| `connect-src` | kept `api.openai.com`, `tweakcn.com`; dropped bare `ws:`/`wss:` | a host the upstream *declares* is honoured, but only `https://`, no wildcards, and **never the cockpit** (`:174`) — `connect-src https://mso.rahmanef.com` from a compromised upstream is the reach scoping removes. This is not what kills its own socket — §4's missing `Upgrade` is: nothing on the app host answers one, so no `wss://` request is ever made for a policy to judge. What is gone is a socket to any *other* host |
| `style-src`, `font-src` | kept `fonts.googleapis.com`, `fonts.gstatic.com` | declared upstream, so honoured — OpenClaw keeps its webfonts where Hermes, declaring nothing, does not |
| `base-uri` | `'none'` honoured | root-mounted nothing injects `<base href>`, so upstream's stricter value can win (`:104`); single-origin ours must win or relative URLs escape the prefix |
| `frame-ancestors` | overridden to `'self' <cockpit>` | always ours — being framed by the cockpit is the point. The origin is deployment env only (`origin.ts:101`); resolving to nothing emits `'none'`, so a misconfiguration refuses visibly instead of naming a guessed framer |

One upstream host is refused by **both** policies: `generativelanguage.googleapis.com`,
referenced in `chat-page-DrPkxqJK.js` but absent from OpenClaw's own `connect-src` — so it is
blocked in OpenClaw's own deployment too. It is the one OpenClaw entry in
`PROXY_BLOCKED_EXTERNALS` (`proxy-headers.ts:228`) and the window says *"The Gemini live-audio
socket in chat cannot connect."*

Live, unauthenticated, `curl -sI https://openclaw.mso.rahmanef.com/` returns `401` with
`content-security-policy: default-src 'none'; frame-ancestors 'self' https://mso.rahmanef.com`
and `x-middleware-rewrite: /api/v1/managed-apps/openclaw/proxy` — the host gating and the
framing grant both working, before auth. Full verification set:
[MANAGED-APPS.md §5](./MANAGED-APPS.md).

## 6. Feature discovery for OpenClaw

`discoverOpenClaw()` (`features.ts:75`) reads OpenClaw's **own route table**. Nothing is
hardcoded; there is no plugin-manifest step (Hermes has one, OpenClaw exposes no equivalent).

1. `GET http://127.0.0.1:18789/`, find `./assets/app-route-paths-*.js` in the HTML, fetch it,
   parse the `key: { path, aliases }` map (`parseOpenClawRoutePaths`, `feature-parser.ts:126`).
   Today that chunk is `app-route-paths-Ckh-KQjG.js`.
2. Empty? Parse the `index-*.js` chunk's page and settings route factories (`:133`).
3. Still empty (gateway down)? Read the same `app-route-paths-*.js` from disk under
   `OPENCLAW_CONTROL_UI_DIST` or `~/.local/lib/node_modules/openclaw/dist/control-ui`. That
   lookup is a glob, so it is version-independent — this is what keeps the launchpad populated
   while the gateway is stopped.

The parser keys on **property names** (`path`, and the map key), which survive minification;
the wrapping variable does not, so the regex is deliberately anchor-free
(`feature-parser.ts:23`). **Titles come from the map KEY, not the path**
(`feature-parser.ts:8`, `:120`) — which is why `/settings/general` is titled "Settings" (key
`config`) and `/dreaming` is "Dreaming" (key `dreams`); an unknown key is title-cased.

Live result, reproduced end to end: **26 routes, 24 offered.**

- `/chat` `/overview` `/activity` `/agents` `/instances` `/sessions` `/usage` `/debug` `/logs`
  `/skills` `/skills/workshop` `/cron` `/tasks` `/nodes` `/dreaming`
- `/settings/{channels,general,communications,appearance,automation,mcp,infrastructure,ai-agents,worktrees}`
- **Not offered**: `/workboard` (feature flag) and `/plugin` (a plugin host panel) are marked
  `available: false` (`feature-parser.ts:12`) and filtered out of the dock
  (`dynamic-features.tsx:49`) rather than shipped as dead tiles.

**The tripwire.** `checked()` (`feature-parser.ts:58`) accepts a run only if it has **≥ 12
entries and includes `/chat`**; otherwise the *whole* run is discarded, so a route-map
reshuffle that breaks the regex yields **zero** tiles, never a plausible partial list.

**Exact symptom when an upgrade breaks it:** the OpenClaw workspace keeps only the shared apps
(Terminal, Files, Assistant, Monitor, Settings) and every OpenClaw tile disappears from dock and
Launchpad. `/api/v1/managed-apps/openclaw/features` still answers `200 {"features":[]}` — a
`503` only happens if discovery *throws*. The status card, the proxy and the CLI view are
unaffected, so the dashboard stays reachable. Results cache 60 s (`features.ts:15`) and nothing
invalidates on upgrade, so a fix or a new upstream route appears within a minute. Unlike Hermes
the primary source is **the live gateway**, so if it ever serves a different bundle than the one
on disk, step 1 wins and the tile list changes when the gateway stops.

## 7. Upgrade and operational notes

OpenClaw updates itself, and it already has everything an update centre would drive:
`openclaw update` (`--channel stable|extended-stable|beta|dev`, `--dry-run`, `--no-restart`,
plus `update status | repair | wizard`), `openclaw doctor --post-upgrade` for plugin-compat
findings, `openclaw uninstall`. MSO has **no update centre** — no check-update, channels,
update, rollback or install wizard (see [MANAGED-APPS.md §8](./MANAGED-APPS.md)). Nothing in
MSO's action set writes upstream state, which is why the current surface is safe. OpenClaw also
snapshots its own config across an upgrade (`openclaw.json.pre-update`, `.last-good`), so a
config regression is recoverable with its own tooling and needs nothing from MSO.

Re-check after any OpenClaw upgrade:

| Check | Why |
|---|---|
| `systemctl --user list-units '*openclaw*'` | `openclaw daemon install` **writes the unit**, and MSO's catalog hard-codes candidate names. A rename means a catalog edit: detection would report `not-installed` rather than guess (§2) |
| tile count (open the OpenClaw workspace) | a route-map reshape trips the tripwire → 0 tiles |
| `curl -s 127.0.0.1:18789/ \| grep app-route-paths` | the asset hash changes every release; live discovery follows the HTML so it self-heals, and the on-disk fallback globs |
| `curl -s 127.0.0.1:18789/health` and `openclaw --version` | the only health signal MSO uses, and the string shown verbatim on the card |
| the CLI toggles | `feature-cli.test.ts` pins the verb map; a renamed subcommand should fail that test, not surprise a user |
| its `Content-Security-Policy` | the intersection is only as good as the source; see below |

**What an upgrade can break in the frame.** OpenClaw already pins its inline scripts by hash,
so a policy *tightening* is mostly absorbed — ours only gets tighter and its own hashes travel.
Three concrete edges:

- **A new inline script without a new hash** breaks in the frame *and* in OpenClaw's own
  deployment (root-mounted MSO adds no `'unsafe-inline'` back and pins nothing,
  `proxy-csp.ts:233`), so upstream sees it first.
- **A new external `connect-src`/`style-src` host** is honoured automatically if declared
  (https, non-wildcard, not the cockpit). One it *calls without declaring* stays blocked, and
  only reaches the window's notice if added to `PROXY_BLOCKED_EXTERNALS` by hand.
- **Switching from hashes to a nonce** makes `script-src` unintersectable: nonces are never
  copied and dropping one would leave `'none'`, so `intersect()` hands the directive back to
  ours (`proxy-csp.ts:188`) — root-mounted that means `'unsafe-inline'` returns and script
  containment loosens to the origin scope alone.

**Known divergences from this integration:**

- **No restore path** ([MANAGED-APPS.md §8](./MANAGED-APPS.md)): `backup` (§2) copies the state dir,
  nothing reads a snapshot back — a rollback is `openclaw backup`'s archive or a manual `cp -a`.
- **The panels stay empty** (§4) and will until a Node-runtime WebSocket proxy exists outside
  the App Router, with the origin and token containment re-derived for sockets — and
  `controlUi.allowedOrigins` extended to the app host.
- No MSO surface covers `openclaw daemon`, sandboxes, node hosts, channels or exec approvals;
  those stay with the CLI and the Control UI. `dashboardAvailable` is computed, never consumed.
